## Chosen: pothole detection

### Roboflow pothole dataset (training data)

- Already in Tair's Roboflow workspace as project `pothole-idtb2-pr1td`. A YOLO26 Small model was trained on it in Roboflow on 3 November 2026 (input 640×640, online augmentations: flip, brightness, blur, mosaic, saturation, hue, grayscale, affine).
- Still to record: the original Roboflow Universe dataset name, author, image count, class list and licence (task D-1).
- The syllabus allows "only open, licence-clean sources: data.egov.kz, stat.gov.kz, Kaggle Datasets, UCI Machine Learning Repository, OpenML" (Syl p.9). Roboflow Universe is not on the list, so D-1 also looks for the same dataset on Kaggle, and the team asks the instructor if there is none.
- That Roboflow-trained model is not used anywhere in the results or the app. The experiment trains its own models with `ml/train.py`. A metric from the Roboflow dashboard must never appear on a slide as the team's result.

### EDK Global Potholes Dataset (Hugging Face)

- Link: https://huggingface.co/datasets/Outerview/global-potholes-dataset (the repository now resolves to `EDK-Earth/global-potholes-dataset`).
- Licence: CC-BY-4.0. Not gated.
- Size: 29,261 rows in the CSV. Images are one 1.28 GB zip. Also provided as Parquet and GeoJSON.
- Columns: `id, latitude, longitude, source, region, filename`. There are **no bounding boxes** and no severity labels.
- Labelling: the dataset card says imagery comes from Mapillary and the pothole labels were generated by EDK's own AI models. They are not human annotations.
- Coverage: 101 regions. Largest are United States 3,854, United Kingdom 3,482, Australia 3,377, Japan 3,235, Canada 3,167. No rows are tagged Kazakhstan.
- How we use it: not for training, because model-generated labels without boxes are not ground truth for a detector. It is useful as (1) realistic latitude and longitude data for the map and analytics pages, with attribution, and (2) a pool of unseen street-level photos to show qualitative results from our model.

## Considered and parked

### PIO: broiler chicken detection ("the birds idea")

- Boniche et al., "PIO, A Large-Scale Dataset for Broiler Chicken Detection under Real Poultry Farming Conditions", Scientific Data, DOI 10.1038/s41597-026-07114-5.
- 1,487 manually annotated images with 327,289 chicken instances from commercial and prototype poultry houses. The authors benchmarked three YOLOv10 variants.
- Parked because counting dense, overlapping birds is a harder task, and the pothole model was already training. The same pipeline (YOLO, rules, dashboard) would apply, so it is a possible second module after the defense.
